2. **P1, §2 lines 87 and 90.** The release tests omit the successful handoff. An implementation can retain `shellWindows`, `dispatch`, or `shellBrowser` after a successful `Open()` and still pass the failure tests, the idempotent disposal test, and the handle-count threshold. Require a success trace that checks which acquisitions have been released when `Open()` returns, calls the retained view, then verifies that two disposals release its ownership exactly once. Cover aliased interfaces. Replace the prescribed `FinalReleaseComObject` with release of the references the holder owns, and verify that disposing one of two live holders leaves the other usable. Final release zeroes the shared wrapper’s entire reference count. [Microsoft’s `FinalReleaseComObject` contract](https://learn.microsoft.com/en-us/dotnet/api/system.runtime.interopservices.marshal.finalreleasecomobject)

[Microsoft’s `FindWindowSW` contract](https://learn.microsoft.com/en-us/windows/win32/api/exdisp/nf-exdisp-ishellwindows-findwindowsw)

4. **P2, §2 line 89.** Shell access denial can escape the promised `DesktopUnavailableException` boundary. .NET maps `E_ACCESSDENIED` from a throwing COM call to `UnauthorizedAccessException`, which the listed handlers miss. Cover access denial at the shell-call boundary and assert that the original exception survives as `InnerException`. Also test a negative HRESULT returned directly by `FindWindowSW`, such as `E_NOINTERFACE`, and verify that its error code survives translation. The existing `S_FALSE` case exercises only the missing-window result. [Microsoft’s COM exception mapping](https://learn.microsoft.com/en-us/dotnet/standard/exceptions/handling-com-interop-exceptions) · [Documented `FindWindowSW` results](https://learn.microsoft.com/en-us/windows/win32/api/exdisp/nf-exdisp-ishellwindows-findwindowsw)

5. **P2, §2 line 91.** Installing `DispatcherSynchronizationContext` leaves the STA test runner incomplete. `Task.Yield()` posts a continuation that needs the STA thread to pump its dispatcher. Require the runner to pump until the test completes, propagate test failures, and shut down on success and failure. Assert that the continuation runs on the **same thread ID** as before the await. For MTA rejection, also assert that the activation factory received zero calls. Checking only the exception message allows activation to happen before the guard.
