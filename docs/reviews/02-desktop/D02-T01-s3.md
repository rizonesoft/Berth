2. **P1, lines 118, 121–122 and 125.** The checkpoint compares the deduplicated result with raw `ItemCount`. A correct read fails whenever two shell items share a parsing name ignoring case. Conversely, a reader that merges distinct icons by display name can pass on a desktop with unique labels. Use a fixture containing two distinct parsing names with the same display name and a third item duplicating the first parsing name with different case. Assert that all three were visited, both distinct identities survive, and the first duplicate’s fields are retained. Also cover an empty enumeration returning an empty list.
3. **P1, lines 115, 120, 122 and 125.** Bounds and inverse checks do not prove that `ReadIcons` assigns the right physical position to each icon. Returning one constant in-bounds point can pass the live assertions, and two mutually inverse helpers can agree on the wrong offset. The bounds check also rejects a genuine off-screen position that `MonitorNumbering` is designed to report. Drive public `ReadIcons` with distinct per-item view points and a known nonzero monitor origin. Assert the exact signed coordinates by parsing name, including an off-screen point, and independently assert the expected `ToView` values.
4. **P1, lines 116 and 118–119.** The instruction to free `pOleStr` after `StrRetToStrW` fails assumes the input still belongs to the caller. Microsoft documents that the input `STRRET` is invalid after the call. Specify the ownership transfer, pass the current PIDL for `STRRET_OFFSET`, check the conversion HRESULT, and release each caller-owned allocation exactly once. Exercise the actual conversion path with Unicode text longer than 260 characters, `OFFSET`, `CSTR`, and a conversion failure after an earlier item succeeded. Require a typed failure with no partial result. [Microsoft’s `StrRetToStrW` contract](https://learn.microsoft.com/en-us/windows/win32/api/shlwapi/nf-shlwapi-strrettostrw)
5. **P2, lines 118–119 and 125.** The cleanup tests start after both COM interfaces have been acquired. Also exercise an item disappearing during `GetDisplayNameOf` after a successful first item. A file-not-found HRESULT can surface as `FileNotFoundException`, outside the existing worker helper’s catch list. Require `DesktopUnavailableException` with the original cause so `LayoutService.Capture` takes its desktop-refusal path.
6. **P2, lines 118 and 121.** The promised duplicate warning is optional in production. The acceptance test supplies a real `Log`, while the proposed constructor permits `null` and D03 T01 §3 only says to construct the logger and desktop reader. Require production composition to pass its logger to the reader, and verify that wiring so the warning reaches the configured log.
7. **P2, line 122.** Two consecutive live reads need not return equal lists. Explorer or a sync client can add, remove or move an icon between calls, and the section defines no stable enumeration order. Use a controlled two-read test that changes one icon’s position and asserts the second result by parsing name. That catches a reader which caches its first result, an implementation the proposed equality check would reward.
